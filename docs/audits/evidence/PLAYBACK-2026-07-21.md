# Physical Playback Evidence — 2026-07-21

Scope: read-only production media probes plus local iOS validation. No production data or service configuration was changed.

## Production media

- Soundscape `15` (`龙华巷里烟火喧`) resolves to an AAC mono M4A with a duration of about 435.3 seconds. Full-file mean volume is `-24.7 dB`; the first 15 seconds average `-21.7 dB`. This asset contains audible signal.
- Soundscape `16` (`未命名声景`) resolves to a 30.7-second AAC mono M4A whose mean and maximum volume are both approximately `-91 dB`. This asset is digital silence.
- Soundscape `17` (`九巷风藏旧语声`) resolves to a 699.0-second AAC mono M4A whose mean and maximum volume are both approximately `-91 dB`. This asset is digital silence.
- The media origin returned `Accept-Ranges: bytes`; a 64 KiB first-byte range and a 64 KiB tail range for soundscape `15` both returned HTTP `206`. The M4A metadata atom is at the tail, so player buffering/readiness must remain visible rather than being reported as active playback immediately.

## iOS regression evidence

- RED: `testPlayDoesNotClaimAudioIsPlayingBeforeEngineStartsOutput` failed because the controller set `isPlaying` immediately after calling `AVPlayer.play()`.
- GREEN: playback now follows AVFoundation `timeControlStatus`, exposes an explicit buffering phase, and shows playback errors inside the immersive view.
- Full `scripts/ci.sh` passed after the change, including repository guards, simulator build, unit/contract tests, and the primary-tab UI test.
- A signed Debug build was installed and launched on physical device `ZLIPHONE` with bundle identifier `tech.panor.soundscape`.
- A second RED test reproduced a separate error-boundary bug: failure of the non-critical `/play` telemetry request wrote `.transport` into the shared player error and caused the immersive view to display `网络连接失败，请稍后重试` even though media playback had not failed. The telemetry path now logs failure without altering user playback state.
- A direct AVFoundation probe of soundscape `15` reached `AVPlayerItem.readyToPlay`, transitioned through buffering, entered `AVPlayer.timeControlStatus.playing`, and advanced playback time. This separates the healthy media contract from the telemetry error race.

## Logging limitation

`devicectl --console` attached successfully but did not emit usable app stdout during the capture window. Unified `Logger` diagnostics and DEBUG console diagnostics remain in the installed build, but physical audibility was not claimed without a captured route/volume/playback event and a human listening check.
